Autonomous Navigation Project
SLAM Mapping · A* Planning · AMCL Localization · Pure-Pursuit Control

TurtleBot3 Path-Following Controller

This project implements a complete autonomous navigation pipeline for the TurtleBot3 robot inside the turtlebot3_house Gazebo simulation. The work covers every layer of a standard mobile-robot stack: building a 2D occupancy map with SLAM, planning collision-free paths with a custom A* algorithm, localizing with AMCL, and tracking waypoints with a pure-pursuit feedback controller augmented by a laser-scan safety layer.

Project Overview

A full autonomy chain built on TurtleBot3, demonstrating the integration of perception, planning, and control from first principles.

Course Context

This project was completed as the final report for Autonomous Vehicles (Prof. Stefano Arrigoni, A.Y. 2025/2026) at Politecnico di Milano. The objective was to design and validate a full navigation stack on the TurtleBot3 platform inside the turtlebot3_house Gazebo environment.

The bonus task — closed-loop navigation using AMCL localization and a path-tracking feedback controller — was also completed in full.

High-Level Pipeline

  • Stage 1 — SLAM Mapping: Teleoperate the robot and build a 2D occupancy grid in RViz using SLAM.
  • Stage 2 — A* Planning: Implement a memory-efficient A* planner on the saved occupancy grid; test four start–goal pairs.
  • Stage 3 — AMCL Localization: Load the saved map and initialize the particle filter with a manual pose estimate in RViz.
  • Stage 4 — Feedback Control: Track the planned waypoints with a pure-pursuit controller and a laser-scan safety layer.

Mapping with SLAM and RViz

Before planning can begin, a consistent 2D map of the environment must be built.

Procedure

The turtlebot3_house simulation was launched and the robot was manually driven with teleop_node through every corridor and around every obstacle. While exploring, SLAM incrementally estimated the robot pose and accumulated laser scan observations into a 2D occupancy grid.

Each cell in the resulting grid is labelled as free, occupied, or unknown. Once the map was visually consistent and all accessible areas were covered, it was saved as a fixed reference for planning and navigation.

A critical requirement for the later AMCL stage is that the map covers the full navigable environment — gaps in the map degrade particle-filter localization quality.

Constructed Occupancy Map

The RViz view shows the completed occupancy grid after manually exploring the house environment. White cells are free space, black cells are obstacles, and the teal-shaded region is unmapped territory at the time of saving.

A* Global Planning

A memory-efficient A* planner was implemented from scratch to find collision-free paths on the full-size occupancy grid.

Grid Formulation

Map to Graph

The saved occupancy image is converted to a binary matrix BW ∈ {0,1} where 1 = free and 0 = obstacle. Start and goal are defined in grid coordinates and validated to lie on free cells.

BW(r,c) = 1 → free cell BW(r,c) = 0 → obstacle
Search Algorithm

A* with f = g + h

Neighbors are generated on-the-fly (no pre-built adjacency list), keeping memory use constant regardless of grid size. The Euclidean heuristic guides search toward the goal efficiently.

f(q) = g(q) + h(q) h(q) = √((x_g−x)² + (y_g−y)²)
Output

Waypoint Sequences

For each start–goal pair the discrete grid path is converted back to metric coordinates and saved to a file. Planning is done offline once; the same waypoint list is reused for all navigation runs.

grid cell [r,c] → metric (x,y) [m] → waypoint file

Each of the four map variants (House_1 through House_4) uses a different start and goal position chosen to test distinct navigation scenarios — short straight corridors, multi-room routes, and tight corner navigation. Control System Design

The navigation controller combines a nominal pure-pursuit path-following law with a reactive laser-scan safety layer.

Waypoint Tracker (Assignments)

For the assignment stages, each waypoint was tracked with a proportional distance-and-heading law. The robot drives toward the active waypoint, decelerating as it gets closer, and aligns its heading in place before advancing to the next waypoint.

d = √((x_g−x)² + (y_g−y)²) α = wrap(atan2(y_g−y, x_g−x) − ψ) v = sat(k_v · d, 0, v_max) ω = sat(k_ω · α, −ω_max, ω_max) reach condition: d ≤ r_goal = 0.05 m align condition: |e_ψ| ≤ 3°
The variable gain k_thrust = sat(d / d_max, 0, 1) scales the forward speed with remaining distance, giving smooth deceleration without a separate speed scheduler.

Pure-Pursuit + Safety Layer (Project)

The project controller selects a look-ahead point at fixed distance L_d ahead on the path, transforms it to the robot frame, and computes a curvature command. Speed is automatically reduced in sharp turns.

κ = 2 y_r / L_d² ω_track = v_track · κ v_track = v_max / (1 + k_slow |ω_track|)

The laser-scan safety layer runs in parallel and blends in a danger-weighted avoidance signal:

v = min(v_track, v_cap) ω = (1−λ)·ω_track + λ·ω_avoid emergency override (d_min < d_emg): v = 0, ω = ω_avoid

Speed Cap from LaserScan

Two distance measures are computed from the front laser beams: d_min (minimum range) and d_p (low percentile of front ranges). A smooth ramp limits forward speed based on proximity to obstacles.

v_cap = 0 if d_p ≤ d_stop v_cap = v_max if d_p ≥ d_slow v_cap = v_max · η otherwise (smooth ramp η ∈ (0,1))
The danger weight λ ∈ [0,1] increases as the robot approaches obstacles, smoothly handing steering authority from the path tracker to the avoidance signal before any emergency stop is required.

AMCL Localization

Accurate continuous pose estimation is required before the feedback controller can execute the planned path.

Particle Filter Initialization

AMCL was run against the saved occupancy map. Before the robot started moving, the particle filter was initialized using the RViz "2D Pose Estimate" tool, which seeds the distribution close to the robot's true pose. Without this step, the initial uncertainty is large and the robot may diverge before converging.

After initialization, AMCL continuously updates the particle weights using incoming laser scans and the motion model, providing a reliable (x, y, ψ) estimate for the waypoint tracker.

Waypoint Tracking Logic

Once AMCL provides the pose, the controller loops over the waypoint list:

  • Select the next waypoint (x_g, y_g).
  • Compute Euclidean distance d and heading error α.
  • Output saturated linear and angular velocity commands.
  • Advance to the next waypoint when d ≤ r_goal.
v = sat(k_v · d, 0, v_max) ω = sat(k_ω · α, −ω_max, ω_max)

Conclusion

The project demonstrated the complete autonomy chain for mobile robot navigation, from raw sensor data to closed-loop path execution.

Key Findings

  • SLAM produced a consistent, usable occupancy map after a single teleoperation session covering the full accessible area.
  • A* with the Manhattan heuristic explored up to 44 % fewer nodes than Dijkstra while finding paths of identical geometric quality.
  • The initial AMCL pose estimate via RViz is critical — without it, the particle filter takes many seconds to converge, causing path deviations.
  • The danger-weighted mixing law between pure pursuit and obstacle avoidance produced smooth, collision-free behavior without hard mode switches.

Full Autonomy Chain

The project validates the standard mobile-robot navigation pipeline end-to-end:

  • Build a map with SLAM.
  • Plan globally on the map with A*.
  • Localize in the map with AMCL.
  • Drive to the goal with feedback control.
Each stage was implemented from scratch in ROS 2, with MATLAB used for real-time path visualization and post-processing of odometry data.
