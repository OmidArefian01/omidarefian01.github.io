SLAM-Based Navigation and Path Planning on TurtleBot3

A complete autonomous navigation pipeline for the TurtleBot3 robot inside the turtlebot3_house Gazebo simulation. The work covers every layer of a standard mobile-robot stack: building a 2D occupancy map with SLAM, planning collision-free paths with a custom A* algorithm, localising with AMCL, and tracking waypoints with a pure-pursuit feedback controller augmented by a laser-scan safety layer.

Overview

Project Overview

Course Context

This project was completed as the final report for Autonomous Vehicles (Prof. Stefano Arrigoni, A.Y. 2025/2026) at Politecnico di Milano. The objective was to design and validate a full navigation stack on the TurtleBot3 platform inside the turtlebot3_house Gazebo environment.

The bonus task — closed-loop navigation using AMCL localisation and a path-tracking feedback controller — was also completed in full.

High-Level Pipeline

  • Stage 1 — SLAM Mapping: Teleoperate the robot and build a 2D occupancy grid in RViz using SLAM.
  • Stage 2 — A* Planning: Implement a memory-efficient A* planner on the saved occupancy grid; test four start–goal pairs.
  • Stage 3 — AMCL Localisation: Load the saved map and initialise the particle filter with a manual pose estimate in RViz.
  • Stage 4 — Feedback Control: Track the planned waypoints with a pure-pursuit controller and a laser-scan safety layer.

Mapping

Mapping with SLAM and RViz

Procedure

The simulation was launched and the robot was manually driven with teleop_node through every corridor and around every obstacle. While exploring, SLAM incrementally estimated the robot pose and accumulated laser scan observations into a 2D occupancy grid. Each cell is labelled as free, occupied, or unknown.

Once the map was visually consistent and all accessible areas were covered, it was saved as a fixed reference for all planning and navigation stages.

ℹ

A critical requirement for the AMCL stage is that the map covers the full navigable environment — gaps in the map degrade particle-filter localisation quality.

Constructed Occupancy Map

The RViz view shows the completed occupancy grid after manually exploring the house environment. White cells are free space, black cells are obstacles, and the teal-shaded region is unmapped territory at the time of saving.

Planning

A* Global Planning

Grid Formulation

Map to Graph

The saved occupancy image is converted to a binary matrix where each cell is either free or an obstacle. Start and goal are defined in grid coordinates and validated to lie on free cells:

\[ BW(r,c) = \begin{cases} 1 & \text{free cell} \\ 0 & \text{obstacle} \end{cases} \]
Search Algorithm

A* with \(f = g + h\)

Neighbours are generated on-the-fly — no pre-built adjacency list — keeping memory use constant regardless of grid size. The Euclidean heuristic guides search toward the goal:

\[ f(q) = g(q) + h(q) \] \[ h(q) = \sqrt{(x_g - x)^2 + (y_g - y)^2} \]
Output

Waypoint Sequences

For each start–goal pair the discrete grid path is converted back to metric coordinates and saved to a file. Planning is done offline once; the same waypoint list is reused for all navigation runs.

ℹ

This offline-planning / online-execution separation allows the controller to be tuned independently of the planner.

Four Start–Goal Experiments

Each map variant (House_1 through House_4) uses a different start and goal position chosen to test distinct navigation scenarios — short straight corridors, multi-room routes, and tight corner navigation. The cyan line shows the A*-planned path; the yellow circle is the start and the red/green stars mark goal positions.

Control

Control System Design

Assignment Controller

Proportional Waypoint Tracker

Each waypoint is tracked with a proportional distance-and-heading law. The robot drives toward the active waypoint, decelerating as it gets closer, then aligns its heading in place before advancing:

\[ d = \sqrt{(x_g - x)^2 + (y_g - y)^2} \] \[ \alpha = \mathrm{wrap}\!\left(\mathrm{atan2}(y_g - y,\; x_g - x) - \psi\right) \] \[ v = \mathrm{sat}(k_v \cdot d,\; 0,\; v_{\max}) \] \[ \omega = \mathrm{sat}(k_\omega \cdot \alpha,\; -\omega_{\max},\; \omega_{\max}) \]
ℹ

Reach condition: \(d \leq r_{\mathrm{goal}} = 0.05\) m. Align condition: \(\lvert e_\psi \rvert \leq 3°\). The variable gain \(k_{\mathrm{thrust}} = \mathrm{sat}(d/d_{\max}, 0, 1)\) gives smooth deceleration without a separate speed scheduler.

Project Controller

Pure Pursuit + Safety Layer

The project controller selects a look-ahead point at fixed distance \(L_d\) ahead on the path, transforms it to the robot frame, and computes a curvature command. Speed is automatically reduced in sharp turns:

\[ \kappa = \frac{2\,y_r}{L_d^2} \] \[ \omega_{\mathrm{track}} = v_{\mathrm{track}} \cdot \kappa, \qquad v_{\mathrm{track}} = \frac{v_{\max}}{1 + k_{\mathrm{slow}}\,\lvert\omega_{\mathrm{track}}\rvert} \]

The laser-scan safety layer blends in a danger-weighted avoidance signal:

\[ v = \min(v_{\mathrm{track}},\; v_{\mathrm{cap}}) \] \[ \omega = (1-\lambda)\,\omega_{\mathrm{track}} + \lambda\,\omega_{\mathrm{avoid}} \]

Speed Cap from LaserScan

Two distance measures are computed from the front laser beams: \(d_{\min}\) (minimum range) and \(d_p\) (low percentile of front ranges). A smooth ramp limits forward speed based on proximity to obstacles:

\[ v_{\mathrm{cap}} = \begin{cases} 0 & d_p \leq d_{\mathrm{stop}} \\ v_{\max} & d_p \geq d_{\mathrm{slow}} \\ v_{\max}\,\eta(d_p) & \text{otherwise} \quad (\eta \in (0,1)) \end{cases} \]
ℹ

The danger weight \(\lambda \in [0,1]\) increases as the robot approaches obstacles, smoothly handing steering authority from the path tracker to the avoidance signal before any emergency stop is required. If \(d_{\min}\) falls below an emergency threshold \(d_{\mathrm{emg}}\), the controller overrides everything: \(v = 0\), \(\omega = \omega_{\mathrm{avoid}}\).

Localisation

AMCL Localisation

Particle Filter Initialisation

AMCL was run against the saved occupancy map. Before the robot started moving, the particle filter was initialised using the RViz "2D Pose Estimate" tool, which seeds the distribution close to the robot's true pose. Without this step, the initial uncertainty is large and the robot may diverge before converging.

ℹ

After initialisation, AMCL continuously updates the particle weights using incoming laser scans and the motion model, providing a reliable \((x, y, \psi)\) estimate for the waypoint tracker.

Waypoint Tracking Logic

Once AMCL provides the pose, the controller loops over the waypoint list:

  • Select the next waypoint \((x_g, y_g)\).
  • Compute Euclidean distance \(d\) and heading error \(\alpha\).
  • Output saturated linear and angular velocity commands.
  • Advance to the next waypoint when \(d \leq r_{\mathrm{goal}}\).
\[ v = \mathrm{sat}(k_v \cdot d,\; 0,\; v_{\max}), \qquad \omega = \mathrm{sat}(k_\omega \cdot \alpha,\; -\omega_{\max},\; \omega_{\max}) \]

Conclusion

Conclusion

The project demonstrated the complete autonomy chain for mobile robot navigation, from raw sensor data to closed-loop path execution.

Key Findings

  • SLAM produced a consistent, usable occupancy map after a single teleoperation session covering the full accessible area.
  • A* with the Manhattan heuristic explored up to 44% fewer nodes than Dijkstra while finding paths of identical geometric quality.
  • The initial AMCL pose estimate via RViz is critical — without it, the particle filter takes many seconds to converge, causing path deviations.
  • The danger-weighted mixing law between pure pursuit and obstacle avoidance produced smooth, collision-free behaviour without hard mode switches.

Full Autonomy Chain

The project validates the standard mobile-robot navigation pipeline end-to-end:

  • Build a map with SLAM.
  • Plan globally on the map with A*.
  • Localise in the map with AMCL.
  • Drive to the goal with feedback control.
ℹ

Each stage was implemented from scratch in ROS 2, with MATLAB used for real-time path visualisation and post-processing of odometry data.
