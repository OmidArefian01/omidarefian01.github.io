Design of a Multiplicative EKF for UAV State Estimation

An independent Multiplicative Extended Kalman Filter (MEKF) designed to reconstruct the full pose of a drone — position, velocity, attitude, and sensor biases — from raw IMU, GPS, barometer, and magnetometer data. The filter runs entirely independently of the onboard autopilot and is validated against PX4 SITL estimates in Python.

Project Overview

The goal is to build a physically meaningful, fully independent drone state estimator that does not rely on the autopilot's internal filter output.

Motivation

Commercial autopilots such as PX4 provide high-quality onboard state estimates, but these are not suitable as a standalone research estimator because the internal filter details are opaque and the output mixes sensor fusion with control feedback. This project implements an independent MEKF that consumes only raw sensor streams, propagates the drone state from inertial measurements, and corrects it with GPS, barometer, and magnetometer updates.

The PX4 estimates are logged in parallel and used only as a comparison reference for RMSE evaluation — they do not feed into the filter in any way.

State Vector

The filter maintains a 20-dimensional nominal state and a 19-dimensional error state. The quaternion contributes only 3 DOF via the multiplicative error δθ, not 4, preserving the unit-norm constraint without explicit re-normalization:

Nominal state x ∈ ℝ²⁰: p ∈ ℝ³ position (NED) v ∈ ℝ³ velocity (NED) q ∈ ℝ⁴ attitude quaternion b_g ∈ ℝ³ gyroscope bias b_a ∈ ℝ³ accelerometer bias b_m ∈ ℝ³ magnetometer bias b_b ∈ ℝ¹ barometer bias Error state δx ∈ ℝ¹⁹: δθ replaces δq (3-DOF multiplicative)

Estimator Architecture

The MEKF follows the standard predict–correct cycle, with the IMU driving high-rate prediction and GPS, barometer, and magnetometer providing low- to medium-rate corrections.

High Rate · ~200 Hz

IMU Prediction

At every new IMU sample the bias-corrected gyroscope propagates the quaternion multiplicatively and the bias-corrected accelerometer — rotated into the NED navigation frame and augmented with gravity — propagates velocity and position.

ω̂ = ω_m − b̂_g f̂ = f_m − b̂_a â_n = R_nb(q̂) f̂ + g_n p̂⁻ = p̂⁺ + v̂⁺Δt + ½â_nΔt² v̂⁻ = v̂⁺ + â_nΔt q̂⁻ = q̂⁺ ⊗ δq(ω̂Δt)
Low Rate · ~5 Hz

GPS + Baro Update

Whenever a new GPS or barometer measurement arrives the filter runs a standard EKF correction. GPS provides a 3D position anchor and a 2D horizontal velocity constraint; the barometer provides a scalar vertical correction that simultaneously estimates the pressure-altitude offset.

y_k = z_k − h(x̂⁻_k) S_k = H_k P⁻_k H_kᵀ + R_k K_k = P⁻_k H_kᵀ S_k⁻¹ δx̂_k = K_k y_k x̂⁺_k = x̂⁻_k ⊞ δx̂_k
Medium Rate · ~50 Hz

Magnetometer Update

The magnetometer corrects yaw and magnetometer bias via a normalized horizontal-vector update and a separate z-channel update. A norm gate and a heading gate reject distorted measurements before they can corrupt attitude.

m̂_b = R_nb(q̂)ᵀ m_n^ref + b̂_m h_m,xy = [m̂_b,x m̂_b,y] / ‖m̂_b,xy‖ h_m,z = m̂_b,z / ‖m_n^ref‖

PX4 SITL Simulation Environment

The validation environment uses PX4 Software-In-The-Loop running the full PX4 flight stack inside Gazebo Sim. The x500 quadrotor model is loaded into a realistic outdoor scene (Baylands park environment). All MAVLink telemetry streams are exposed over UDP: the Python MEKF reads raw sensor streams via pymavlink while QGroundControl connects simultaneously for flight monitoring. PX4's onboard EKF2 estimates are logged only for comparison purposes.

Coordinate Frames and Sensor Streams

The filter uses two coordinate frames and five MAVLink data streams divided into estimation inputs and comparison-only references.

Coordinate Frames

All position and velocity states are represented in the local NED (North-East-Down) navigation frame, with the origin set at the first valid GPS fix. The body frame is attached to the drone; IMU and magnetometer measurements arrive in this frame. The attitude quaternion Rnb(q) rotates body-frame vectors into the navigation frame:

u_n = R_nb(q) · u_b
In NED, altitude is the negative of the down coordinate p_D. GPS latitude/longitude/altitude are converted into local NED on arrival using the first valid GPS sample as origin.

MAVLink Streams Used

HIGHRES_IMU Gyro, accelerometer, magnetometer — primary prediction and mag update source
GPS_RAW_INT Latitude, longitude, altitude, ground speed, course-over-ground
SCALED_PRESSURE Absolute pressure → relative altitude → vertical correction
LOCAL_POSITION_NED · ATTITUDE PX4 internal estimates — comparison only, never fed into the MEKF

State Propagation Model

The prediction step integrates the full nonlinear dynamics at IMU rate, then propagates the error-state covariance through the linearized transition Jacobian.

Nominal State Propagation

At each IMU step the estimated biases are subtracted, the corrected specific force is rotated into NED and added to gravity, and the resulting acceleration drives Euler integration of position and velocity. The quaternion is updated multiplicatively using the gyroscope-derived rotation increment:

â_n,k = R_nb(q̂_k)(f_m,k − b̂_a,k) + g_n p̂⁻_k+1 = p̂⁺_k + v̂⁺_k Δt + ½ â_n,k Δt² v̂⁻_k+1 = v̂⁺_k + â_n,k Δt q̂⁻_k+1 = q̂⁺_k ⊗ δq(ω̂_k Δt)
Biases are modeled as random walks propagated with zero dynamics — only their covariance entries grow with the corresponding process noise during prediction.

Covariance Propagation

The 19×19 error-state covariance is propagated through the linearized error-state transition matrix Fk, computed numerically using boxplus and boxminus operations on the SO(3) manifold:

P⁻_k+1 = F_k P⁺_k F_kᵀ + Q_k

Qk is the discrete process-noise covariance, tuned to reflect IMU noise spectral density and bias instability. The error-state formulation keeps the quaternion unit-norm constraint satisfied at every step without explicit re-normalization in the covariance equations.

Measurement Updates and Sensor Fusion

Five separate update channels handle GPS position, GPS velocity, barometer altitude, magnetometer horizontal vector, and magnetometer z-component.

GPS Position Update

The GPS position update directly observes the position state:

z_gps,p = [p_N^gps p_E^gps p_D^gps]ᵀ h_gps,p(x) = [p_N p_E p_D]ᵀ y_gps,p = z_gps,p − p̂

GPS Horizontal Velocity Update

When ground speed and course-over-ground are available, horizontal velocity components are constructed and used as an additional correction. A gate rejects measurements with excessive velocity innovation:

v_N^gps = s^gps · cos(χ^gps) v_E^gps = s^gps · sin(χ^gps) h_gps,v(x) = [v_N v_E]ᵀ

Barometer Update

A scalar correction for the vertical channel. The barometer bias bb absorbs any constant pressure-to-altitude offset, preventing the vertical position state from being corrupted by systematic sensor error:

z_b = p_D + b_b + n_b h_b(x) = p_D + b_b y_b = z_b − (p̂_D + b̂_b)

Magnetometer Updates

Two channels constrain yaw and magnetometer bias. A norm gate and heading gate reject measurements with suspected magnetic disturbances:

m̂_b = R_nb(q̂)ᵀ m_n^ref + b̂_m Horizontal: h_m,xy(x) = [m̂_b,x m̂_b,y] / ‖m̂_b,xy‖ Z-channel: h_m,z(x) = m̂_b,z / ‖m_n^ref‖
Gating on both the magnetic norm and the heading error prevents large yaw jumps caused by magnetic disturbances near metallic structures or electrical equipment.

Results

The MEKF was validated in PX4 SITL across a full 80-second flight maneuver sequence covering takeoff, aggressive lateral and vertical motion, and landing. The estimator output is compared against PX4's onboard EKF2 estimates across attitude, velocity, and position.

Attitude Comparison — Roll, Pitch, Yaw

The MEKF attitude (blue solid line) tracks the PX4/SITL reference (orange dashed) very closely for roll and pitch throughout the entire flight. The yaw channel shows a slowly varying offset during the most aggressive maneuvers between 20–50 s, which is expected given that the only yaw correction comes from the magnetometer — a single-axis sensor susceptible to temporary disturbances. The filter recovers correctly once the maneuver ends.

Velocity Comparison — v_x, v_y, v_z

Horizontal velocity estimates (v_x and v_y) match the PX4 reference almost exactly across the full flight envelope, including peak velocities above 4 m/s. The vertical velocity v_z shows slightly more noise than the PX4 reference due to the barometer update rate and the absence of a dedicated vertical velocity sensor, but the overall trend and magnitude are well captured throughout.

Position Comparison — x, y, z

Position estimates in all three axes remain tightly coupled to the PX4 reference throughout the flight, including during the largest displacements of roughly 40 m in the x-direction and −15 m in altitude. The close agreement demonstrates that the GPS position and velocity updates, combined with barometer altitude correction, effectively prevent inertial drift over the full 80-second flight duration.

RMSE Summary

Root-mean-square errors computed over the full flight log against PX4/SITL reference estimates. Position errors are sub-0.23 m across all axes; roll and pitch errors are below 0.4°. Yaw shows the largest error — consistent with magnetometer-only heading correction and the absence of a dual-antenna GPS for direct yaw measurement.

Extension to a Real Drone

The SITL-validated estimator is now being adapted for deployment on physical hardware in collaboration with SunCubes.

🛸

In Progress · SunCubes Company

The MEKF is currently being extended and redesigned for real hardware deployment at SunCubes, a drone technology company. The transition from SITL to a physical drone introduces new challenges: real sensor noise characteristics, vibration-induced IMU corruption, actual GPS multipath, magnetic interference from motors, and latency in the MAVLink communication link — all of which require retuning and structural changes to the filter. This ongoing work is being carried out on SunCubes hardware running PX4.

Key Differences: SITL → Real Hardware

  • IMU noise: Real MEMS IMUs have vibration aliasing, temperature-dependent bias drift, and correlated noise requiring characterization from static and hover logs.
  • GPS quality: Real GPS is subject to multipath, HDOP variation, and latency jitter that make position and velocity gating more critical.
  • Magnetometer disturbances: Motor currents and ESC switching create magnetic interference far stronger than in simulation.
  • Timing: Real MAVLink streams arrive with variable latency; timestamp alignment between sensors needs explicit handling.

Planned Improvements

  • Empirical noise covariance identification from static and hover flight logs.
  • Adaptive measurement gating based on GPS fix quality and HDOP.
  • Vibration pre-filtering on the accelerometer channel tuned to rotor harmonics.
  • Soft magnetic calibration to reduce motor-current-induced heading errors.
  • Dual-antenna GPS heading source to replace magnetometer-only yaw estimation and eliminate the dominant RMSE term.
The SITL validation baseline provides a clean regression reference: any change that degrades SITL RMSE below the values in the table above is rejected before being tested on hardware.
