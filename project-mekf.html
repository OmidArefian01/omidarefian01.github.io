Design of a Multiplicative EKF for UAV State Estimation

An independent Multiplicative Extended Kalman Filter (MEKF) designed to reconstruct the full pose of a drone — position, velocity, attitude, and sensor biases — from raw IMU, GPS, barometer, and magnetometer data. The filter runs entirely independently of the onboard autopilot and is validated against PX4 SITL estimates in Python.

Project Overview

The goal is to build a physically meaningful, fully independent drone state estimator that does not rely on the autopilot's internal filter output.

Motivation

Commercial autopilots such as PX4 provide high-quality onboard state estimates, but these estimates are not suitable as a research baseline because the internal filter details are opaque and the output mixes sensor fusion with control feedback. This project implements an independent MEKF that consumes only raw sensor streams, propagates the drone state from inertial measurements, and corrects it with GPS, barometer, and magnetometer updates.

The PX4 estimates are logged in parallel and used only as a comparison reference for RMSE evaluation — they do not feed into the filter in any way.

State Vector

The filter maintains a 20-dimensional nominal state and a 19-dimensional error state (the quaternion contributes 3 DOF via the multiplicative error δθ, not 4):

Nominal state x ∈ ℝ²⁰: p ∈ ℝ³ position (NED) v ∈ ℝ³ velocity (NED) q ∈ ℝ⁴ attitude quaternion b_g ∈ ℝ³ gyroscope bias b_a ∈ ℝ³ accelerometer bias b_m ∈ ℝ³ magnetometer bias b_b ∈ ℝ¹ barometer bias Error state δx ∈ ℝ¹⁹: δθ replaces δq (3-DOF multiplicative)

Estimator Architecture

The MEKF follows the standard predict–correct cycle, with the IMU driving high-rate prediction and GPS, barometer, and magnetometer providing low- to medium-rate corrections.

High Rate · ~200 Hz

IMU Prediction

At every new IMU sample the bias-corrected gyroscope propagates the quaternion and the bias-corrected accelerometer — rotated into the NED navigation frame and augmented with gravity — propagates velocity and position.

ω̂ = ω_m − b̂_g f̂ = f_m − b̂_a â_n = R_nb(q̂) f̂ + g_n p̂⁻ = p̂⁺ + v̂⁺Δt + ½â_nΔt² v̂⁻ = v̂⁺ + â_nΔt q̂⁻ = q̂⁺ ⊗ δq(ω̂Δt)
Low Rate · ~5 Hz

GPS + Baro Update

Whenever a new GPS or barometer measurement arrives the filter runs a standard EKF correction step. GPS provides a 3D position anchor and a 2D horizontal velocity constraint; the barometer provides a scalar vertical correction that also estimates the pressure-altitude offset.

y_k = z_k − h(x̂⁻_k) S_k = H_k P⁻_k H_kᵀ + R_k K_k = P⁻_k H_kᵀ S_k⁻¹ δx̂_k = K_k y_k x̂⁺_k = x̂⁻_k ⊞ δx̂_k
Medium Rate · ~50 Hz

Magnetometer Update

The magnetometer corrects yaw and magnetometer bias. A reference field is built from the initial measurement; during filtering the predicted body-frame field is compared against this reference via a normalized horizontal-vector update and a separate z-channel update.

m̂_b = R_nb(q̂)ᵀ m_n^ref + b̂_m h_m,xy(x) = [m̂_b,x m̂_b,y] / ‖m̂_b,xy‖ h_m,z(x) = m̂_b,z / ‖m_n^ref‖

PX4 SITL + QGroundControl Setup

The validation environment uses PX4 Software-In-The-Loop (SITL), which runs the full PX4 flight stack in simulation and exposes all MAVLink telemetry streams over UDP. QGroundControl connects to the same instance for monitoring, while the Python MEKF reads the raw sensor streams simultaneously via pymavlink. PX4's onboard EKF2 estimates are logged only for comparison purposes.

Coordinate Frames and Sensor Streams

The filter uses two coordinate frames and five MAVLink data streams divided into estimation inputs and comparison-only references.

Coordinate Frames

All position and velocity states are represented in the local NED (North-East-Down) navigation frame. The origin is set at the first valid GPS fix. The body frame is attached to the drone; IMU and magnetometer measurements arrive in this frame. The attitude quaternion Rnb(q) rotates body-frame vectors into the navigation frame:

u_n = R_nb(q) · u_b
In NED, altitude is the negative of the down coordinate p_D. GPS latitude/longitude/altitude are converted into local NED on arrival.

MAVLink Streams Used

HIGHRES_IMU Gyro, accelerometer, magnetometer — primary prediction + mag update source
GPS_RAW_INT Latitude, longitude, altitude, ground speed, course-over-ground
SCALED_PRESSURE Absolute pressure → relative altitude → vertical correction
LOCAL_POSITION_NED · ATTITUDE PX4 internal estimates — comparison only, never fed into the MEKF

State Propagation Model

The prediction step integrates the full nonlinear dynamics at IMU rate, then propagates the error-state covariance through the linearized transition Jacobian.

Nominal State Propagation

At each IMU step the estimated biases are subtracted, the corrected specific force is rotated into NED and added to gravity, and the resulting acceleration drives simple Euler integration of position and velocity. The quaternion is updated multiplicatively using the gyroscope-derived rotation increment:

â_n,k = R_nb(q̂_k)(f_m,k − b̂_a,k) + g_n p̂⁻_k+1 = p̂⁺_k + v̂⁺_k Δt + ½ â_n,k Δt² v̂⁻_k+1 = v̂⁺_k + â_n,k Δt q̂⁻_k+1 = q̂⁺_k ⊗ δq(ω̂_k Δt)
Biases are modeled as random walks and propagated with zero dynamics — only the covariance of each bias grows with the corresponding process noise.

Covariance Propagation

The 19×19 error-state covariance is propagated through the linearized error-state transition matrix Fk, which is computed numerically using boxplus and boxminus operations on the manifold:

P⁻_k+1 = F_k P⁺_k F_kᵀ + Q_k

Qk is the discrete process-noise covariance, tuned to reflect IMU noise spectral density and bias instability. The use of the error-state formulation keeps the quaternion constraint (‖q‖ = 1) satisfied at every step without explicit re-normalization in the covariance equations.

Measurement Updates and Sensor Fusion

Five separate update channels handle GPS position, GPS velocity, barometer altitude, magnetometer horizontal vector, and magnetometer z-component.

GPS Position Update

The GPS position update directly observes the position state:

z_gps,p = [p_N^gps p_E^gps p_D^gps]ᵀ h_gps,p(x) = [p_N p_E p_D]ᵀ y_gps,p = z_gps,p − p̂

GPS Horizontal Velocity Update

When ground speed and course-over-ground are available, horizontal velocity components are constructed and used as an additional correction. A gate rejects measurements with excessive velocity innovation:

v_N^gps = s^gps · cos(χ^gps) v_E^gps = s^gps · sin(χ^gps) h_gps,v(x) = [v_N v_E]ᵀ

Barometer Update

A scalar correction for the vertical channel. The barometer bias bb absorbs any constant pressure-to-altitude offset, preventing the vertical position state from being corrupted by a systematic sensor error:

z_b = p_D + b_b + n_b h_b(x) = p_D + b_b y_b = z_b − (p̂_D + b̂_b)

Magnetometer Updates

Two separate magnetometer channels constrain yaw and the magnetometer bias. A norm gate and a heading gate reject measurements with suspected disturbances:

m̂_b = R_nb(q̂)ᵀ m_n^ref + b̂_m Horizontal: h_m,xy(x) = [m̂_b,x m̂_b,y] / ‖m̂_b,xy‖ Z-channel: h_m,z(x) = m̂_b,z / ‖m_n^ref‖
Gating on both the magnetic norm and the heading error prevents large yaw jumps from magnetic disturbances near metallic structures or electrical equipment.

Initialization Procedure

A stationary initialization phase estimates the initial attitude and velocity before the first IMU propagation step.

Startup Sequence

  • Collect a buffer of initial IMU samples and average the accelerometer readings to estimate gravity direction → initial roll and pitch.
  • Average the magnetometer readings and apply tilt compensation to the horizontal projection → initial yaw estimate → initial quaternion q₀.
  • Wait for the first valid GPS fix; set the local NED origin and initialize position from GPS-derived NED coordinates.
  • If GPS horizontal velocity is available, initialize velocity from ground speed and course-over-ground.
  • Initialize the barometer bias so that the first barometer prediction is consistent with the GPS-derived initial altitude.
This initialization assumes the vehicle is approximately stationary at startup — the accelerometer mainly measures gravity and the gyroscope is not rotating — which is satisfied during a typical pre-flight ground check.

Results

The MEKF was validated in PX4 SITL across a full flight maneuver sequence. The estimator output is compared against PX4's onboard EKF2 estimates.

RMSE Summary

Root-mean-square errors computed over the full flight log against PX4 reference estimates. Position errors are sub-0.25 m across all axes; roll and pitch errors are below 0.4°; yaw shows larger error as expected given magnetometer-only heading correction.

Extension to a Real Drone

The SITL-validated estimator is now being adapted for deployment on a physical drone in collaboration with SunCubes.

🛸

In Progress · SunCubes Company

The MEKF is currently being extended and redesigned for real hardware deployment at SunCubes, a drone technology company. The transition from SITL to a physical drone introduces new challenges: real sensor noise characteristics, vibration-induced IMU corruption, actual GPS multipath, magnetic interference from motors, and latency in the MAVLink communication link — all of which require retuning and structural changes to the filter. This ongoing work is being carried out on SunCubes hardware running PX4.

Key Differences: SITL → Real Hardware

  • IMU noise: Simulation noise models are clean Gaussian; real MEMS IMUs have vibration aliasing, temperature-dependent bias drift, and correlated noise that must be characterized from static logs.
  • GPS quality: Real GPS is subject to multipath, HDOP variation, and latency jitter that make position and velocity gating more critical.
  • Magnetometer disturbances: Motor currents and ESC switching create magnetic interference that is far stronger than in simulation.
  • Timing: Real MAVLink streams arrive with variable latency; timestamp alignment between sensors needs explicit handling.

Planned Improvements

  • Empirical noise covariance identification from static and hover flight logs.
  • Adaptive measurement gating based on GPS fix quality and HDOP.
  • Vibration pre-filtering on the accelerometer channel using an onboard low-pass filter tuned to rotor harmonics.
  • Soft magnetic calibration to reduce motor-current-induced heading errors.
  • Real-time performance profiling to ensure the filter runs within the available compute budget on the companion computer.
The SITL validation baseline provides a clean reference for regression testing: any change that degrades SITL RMSE below the values in the table above is rejected before being tested on hardware.
